# NovaFlow 桌面账号模块

[English](README.md) | 中文

本参考文档说明 [src/novaflow](../src/novaflow) 中的原生模块。它们组合安全账号恢复、鉴权模型发现和连接所选 New API 服务器的请求代理。Windows、macOS 和 Linux 的安装包与开发启动都以 NovaFlow 运行，没有开关。服务器默认为 `https://api.lanjiaotrade.com`；未登录时，账号页面上的小字链接可改用其他 New API 站点（例如测试站），已保存的凭证只对签发它的服务器加载。品牌 profile 禁用上游账号、手动 key 和可配置 provider 入口，以及所有 DeepSeek 托管服务：反馈时上传会话日志、DeepSeek 联网搜索与 DeepSeek 搜索、抓取 API、产品遥测，以及只服务 DeepSeek 路由的会话日志、wire 扩展、插件包清单和模型名称标记插件。其系统提示词以 NovaFlow 称呼 Agent，不包含上游 Web GUI 与 harness 开发上下文。应用菜单和侧栏「设置」上方的入口都会在主区域显示原生账号页面，操作仅限自有主框架。桌面授权端点是独立的 New API 接入，不能把管理台 JWT、PAT 或普通 API key 当作桌面授权。

## 原生进程所有权

桌面模型接入仅使用账号。手动提供方适配器、模型提供方设置页和 API Key 应用菜单入口均停用。已有手动凭据不再使用，新的模型选择来自账号目录。

在 Electron 主进程完成 `app.whenReady()` 并取得应用单实例锁后构造 `NovaFlowDesktopRuntime`。使用应用可信用户数据目录中的独立目录创建 `SafeStorageRefreshStore`，传入 `NovaFlowHttpAuthTransport`、原生 `fetch` 和 `shell.openExternal`。账号界面可以使用 `getSnapshot`、`startSignIn`、`cancelSignIn`、`restore`、`refreshAccount`、`refreshCatalog`、`refreshWallet`、`selectGroup` 和 `signOut`。桌面外壳会对每次账号 IPC 验证自有窗口和主框架来源。Preload 在其隔离环境中，只把安全快照和本地化文案渲染进客户端账号页面框架的标题区和内容区，不暴露原始 IPC 或凭证读取方法。离开页面不会中断进行中的登录，可在页面上点「取消登录」停止。它向页面只暴露 `window.dshNovaFlow`：带显示名的登录状态、外壳要求显示账号页面的请求（客户端开始监听前发出的一个请求会保留给它），以及一个挂载操作：接收两个已接入文档的宿主元素，返回卸载函数。页面占满框架而不滚动：宽框架把钱包与账号放在分组卡片旁边，窄框架把它们合成一列紧凑排列，矮框架只让 Auto 顺序列表滚动；只有挤到最小窗口以下的框架（例如窄窗口中手动展开侧栏）才会滚动。

已登录时显示页面会重新读取钱包与本设备用量，同代际的重复请求合并。页面显示刷新中和上次成功更新时间；失败时保留旧数字与时间并标注旧数据，首次失败显示不可用而非零。退出、换账号、换服务器或切组会清除旧身份的数据。金额按站点公开的 `/api/status` 中的显示设置换算：美元、人民币或自定义单位按设定的汇率换算，或显示原始额度，格式与 New API 网页控制台一致。读取到该设置之前，页面显示原始额度。

错误通过固定类别跨 IPC 传递，不携带原始异常或服务器任意文案。账号能力、目录和余额分别报告失败，分别提供重试；网络恢复可重试已保存的登录，登录失效则提供浏览器重新登录。余额收到 401 时最多轮换并重读一次，普通 403 或读取失败不会自行注销。订阅的新状态优先于迟到的状态查询，销毁会等待受跟踪操作结束。

可信 Host 通过经过鉴权的 IPv4 本机请求代理调用 `invoke`。随机本机 capability 仅通过 Node IPC 传递，不进入配置文件、环境变量、renderer 状态或会话内容。每次已准备的请求携带账号与目录代际；在账号或分组变化前准备的请求会被拒绝。返回响应流及请求准入时绑定的分组和模型。账号凭证解析器留在主进程。账号快照和 YAML profile 都不包含 access 或 refresh token。操作系统钥匙串和文件权限保护静态凭证，但不能抵御以同一操作系统用户身份运行的失陷进程。

## 授权与存储

在 macOS 上，Electron 根据应用名称选择钥匙串服务。修复旧安装时，可在私有用户数据目录的 `novaflow-keychain.json` 中写入 `{"version":1,"identity":"hallucodex"}`，固定使用原加密标识；另一个允许的标识是 `novaflow`。文件不存在时保持安装包的默认标识。主程序在就绪前选择该标识，在创建菜单前恢复产品名称。此设置不导出加密密钥，也不改写已保存的凭据。恢复失败时保留加密记录，并提示读取失败，不再假定系统钥匙串未启用。

登录通过系统浏览器使用 S256 PKCE、随机 state，以及监听随机端口、路径为 `/oauth/callback` 的 `127.0.0.1` 本机回调。授权页必须位于所选服务器的来源。回调携带授权码和 state；用户在浏览器中拒绝时携带 `error=access_denied`。监听器以浏览器语言返回静态页面，只用一段按哈希放行的内联样式，不运行任何脚本；浏览器步骤结束后桌面窗口回到前台。校验 refresh 到期时间时容许桌面与服务器之间十分钟的时钟偏差。取消、过期、退出和新登录代际会使旧操作失效，包括延迟返回的网络与存储结果。

Access 凭证只保留在内存。仅包含 refresh 的记录以原子替换方式写入私有加密文件。Linux 必须具有受支持的操作系统钥匙串；`basic_text`、未知后端及不可用的加密均拒绝继续。账号代理在应用实例内串行处理存储和刷新轮换。调用方必须持有单实例锁，存储类本身不提供跨进程协调。

桌面服务在浏览器授权时授予账号允许的具体分组。服务器同时授予 `group:select` 时，账号页面可以把设备移到账号可用的其他分组：先选择候选组，分别预览完整名称、倍率与可换行说明，再点击「切换分组」提交；选择与当前路由不同时显示「放弃更改」，点击即恢复当前路由。`/groups` 为账号给出 `auto` 时，列表还提供 auto：每个请求按顺序尝试一组具体分组，按实际使用分组的倍率计费。设备默认使用完整的全局 Auto 顺序，用户勾选并排序分组（最多为站点的 `max_groups` 个）后改用自己的顺序；全局顺序更长时，由它改成的自定义顺序保留前 `max_groups` 个分组，「恢复全局 Auto」回到全局顺序，另有一个默认勾选的选项，让失败的请求换顺序中的下一个分组重试。授权在 `auto_groups` 中给出顺序（使用全局顺序时为 null），在 `cross_group_retry` 中给出重试选择。选中 auto 时，页面显示目录的 `route_groups` 顺序，其中分组目前都不可用时给出警告。浏览器授权只授予具体分组，所以 auto 在登录后于账号页面中选择。`POST /api/desktop/v1/group` 在同一步中轮换 refresh 凭证，并把会话、路由设置及其用量账目改绑到新分组，设备的用量和额度上限保留；保存新的顺序或重试选择也是一次切换。切换开始即关闭旧组的新请求准入，已开始的流不重发；新目录完整读取后才恢复准入。服务器拒绝的分组保留当前分组和登录状态，成功切组与后续目录或余额读取失败分别显示。没有 `group:select` 时分组固定，要换分组需重新登录。没有客户端分组覆盖。

「刷新账号」即使 access 尚未到期也轮换凭证，同步服务器授予的权限及允许分组，再读取目录与余额；这不是定时刷新。重复刷新合并，并与切组串行执行。旧服务器未授予 `group:select` 不算刷新失败；仅重试目录不会无条件轮换有效凭证。过期或撤销的凭证需要重新登录。刷新或切换分组遇到网络错误时立即重试一次，落在服务器为丢失响应的轮换保留的短暂重试窗口内；再次暂时失败（包括服务器返回 `temporarily_unavailable`）不删除已保存的 refresh，也不把账号能力刷新标为成功。退出本机先阻止请求，再撤销远端授权；结果单独说明远端撤销是否成功。

## 模型与请求代理

Host 保留旧版提供方名称以读取已有会话和解析旧模型调用；旧名称不公布模型，菜单只显示 NovaFlow 路线。目录刷新或退出登录后，旧路线仍返回空列表，不产生提供方加载错误。

当前主程序采用站点登录会话：具体分组来自 `/api/user/self/groups`，账号页面可预览倍率和说明后切换。选中的分组保存在加密会话记录中，刷新和重启后恢复；模型目录按此分组重读，主进程向 `/pg/chat/completions` 注入 `group`，不会修改账号所属组。调用方仍不能覆盖请求路由。站点登录不提供自定义 Auto 顺序或跨组重试；以下桌面授权协议说明适用于独立桌面授权接入。

分组和模型只从经过鉴权的桌面 API 获取，每次目录请求限时 15 秒且限制响应体大小；一条读取失败会取消并等待另一条结束。发现过程拒绝继承分组、`auto` 的其他写法、重复及无效元数据、分组或路由顺序与设备路由不一致的模型目录，以及中途变化的账号；auto 的目录列出顺序中各分组的全部模型。只有完整的账号绑定读取成功后才发布模型并恢复请求，目录失败不阻止独立的钱包读取。公开价格或状态元数据不能授予模型权限，也不能更改服务来源；公开状态只用于决定金额的显示方式。

请求代理支持后端声明的 Chat Completions、Responses 和 Anthropic Messages 端点。`openai-response` 与 `openai-responses` 统一为 `/v1/responses`。未知协议不可用，模型名不代表协议兼容性。每次请求必须选用目录中的模型及其已声明端点。每个模型只在一个已声明端点下列出一次：优先取下文所述匹配到的厂商目录条目的协议；对不上时取模型名开头字母（如 `claude`、`gpt`）相同的厂商模型所用协议；仍对不上则依次取 Chat Completions、Responses、Messages 中第一个已声明的端点。按名称归组让比内置目录更新的模型与同系列模型放在一起，但不提供推理等级。三个原生 provider 复用现有 pi-ai 协议序列化器并关闭自动重试。Anthropic SDK 的本机 x-api-key 和固定 beta 查询由私有代理处理，不作为上游账号凭证转发。请求中的 `group`、`auto_groups` 和 `cross_group_retry` 字段均拒绝，包括序列化过程新增的值。

客户端已验证的方舟 Chat Completions 配置优先于内置 pi-ai 目录。`DeepSeek V4.1 Flash 1017 Eco` 及其原始 ID `deepseek-v4-1-flash-economy-261017` 提供 off、low、high、max，off 发送 `reasoning_effort: none`，默认 high。`Kimi K3.1 Pro` 和 `kimi-k3-1-pro-261024` 提供 low、high、max，默认 max，不提供关闭选项。这些配置保留请求中的对外模型 ID，不发送 `thinking` 字段，并通过 `reasoning_content` 回传原生思考内容。默认档位在准备请求时生效，并记录为适配器默认值，已有会话未保存档位时也适用。[方舟文档](https://docs.volcengine.com/docs/ark/deep-thinking?lang=en) 定义参数，[客户端配置](../../desktop-host/src/novaflow-reasoning.ts) 将完整别名绑定到对应参数。刷新账号时，只会对账号已列出的模型应用配置，不会授予模型权限。新增未知模型或改名后，除非完整 ID 已匹配内置目录，否则需要更新客户端配置。Now API 能转发思考参数，本身不代表它向客户端声明了可选档位。

其他推理等级来自内置的 pi-ai 模型目录。模型 ID 和协议都与某个厂商自营 pi-ai 提供方（Anthropic、OpenAI、xAI、Meta、DeepSeek、Moonshot AI、Kimi Coding、Z.ai、MiniMax、小米、蚂蚁百灵，以及只取 `qwen` 开头模型的阿里千问 Token Plan，按此顺序取第一个匹配）的条目一致时，模型选择器提供该条目的推理等级，请求沿用它的思考参数及相关兼容开关。网关类目录不参与匹配，因为其参数针对网关本身。列在 Chat Completions 下、又没有这类条目的 Gemini 模型，提供 Google 目录中同 ID 条目的推理等级。Gemini 2.5 系列使用思考预算，目录条目没有列出等级，因此提供 low、medium、high 三档（New API 会把它们换算成不同的预算），不提供关闭档。请求以 `reasoning_effort` 发送所选等级，New API 的 Gemini 渠道会把它转成同名的 Gemini 思考等级或思考预算。两种来源都未匹配的模型不提供推理等级。其余厂商开关仍由 pi-ai 自动判断。

每个模型的上下文窗口和输出上限按以下顺序取第一个可用的值：用户为该模型填写的值；服务器模型元数据中配置的值；上文所述匹配到的厂商目录条目；服务器默认值 128000 和 8192，目录用 `capacity_defaults` 标出这些默认值。未提供 `capacity_defaults` 的服务器，其所有值都按已配置处理。用户或服务器给出的输出上限限制每次请求，上下文压缩也为它预留空间；来自厂商目录的输出上限只描述模型能力，每次请求按 pi-ai 的做法把它缩小到上下文剩余空间以内再发送。输出上限大于上下文窗口时，两者中优先级较低的一方调整到相符。输入框模型菜单的“上下文”一行显示所选模型的生效值，点开后的面板列出来源，用户可在其中填写任一项；留空的项采用自动值，“恢复自动”同时清除两项。Host 为已列出的模型提供会话控制器的 `modelCapacity` 服务，并把每次修改转交主进程；主进程保存后重新下发配置，修改才算完成。每项须为不超过 100,000,000 的正整数，输出上限不能大于上下文窗口。这些值对所有对话生效，按服务器和模型保存在[账号工作区](#account-workspaces)所述的账号私有文件里，切换分组和退出登录后仍保留。既没有服务器值也匹配不到目录的模型不会列出，因此无法填写。

请求代理不发送浏览器 Cookie，拒绝重定向，执行配置的字节限制，不自动重试推理请求。401 表示服务器拒绝凭证：关闭新请求准入，通过重新发现目录轮换 access 凭证，设备已被撤销时随之退出登录。403 表示钱包余额、设备额度上限等业务限制，原样返回调用方，目录保持可用。429、服务端错误或网络故障都不切组、不触发第二次可能计费的调用。已开始的流保持原选择。价格、余额、用量结算和渠道路由由服务器负责。

## 账号工作区

桌面安装包随附第三方 `dsh-douyin-comments` 和 `dsh-comment-viewer`，源码保存在[固定来源副本](../third-party/SOURCES.json)。打包时准备好依赖，首次启动不再下载这两个插件。新登录账号默认启用这两个组合包；已有档案保留各自的启停选择，从其他账号继承的用户自行安装插件仍默认关闭。评论词云使用白色背景和深色文字。采集仍沿用上游共享抖音目录与浏览器设置，可选 AI 解读保持原样。实际采集仍需要兼容的 Chromium 和抖音浏览器登录。

桌面端以精确的服务器 origin 和服务器签发的用户 ID 选择独立的数据主目录、配置档案、工作区登记、会话、设置、凭证和 Chromium 分区。修改用户名或分组不会切换工作区。退出登录使用独立的未登录档案。切换时先停止旧 Host、销毁旧界面并关闭其私有请求代理，再启动下一账号；用户主动退出、重新登录或更换服务器时，如果有运行中或已安排的任务，需要先确认。停止或准备失败会阻断访问，并打开桌面错误恢复界面。

首次升级时，现有加密 refresh 记录中的身份拥有原桌面主目录和默认 Chromium 分区，即使网络刷新失败或记录已过期也如此。归属记录位于 Electron userData 下的 `novaflow-account-scopes.json`。没有已保存身份时，旧数据保持未分配，后续登录不会自动取得旧数据。凭证存储无法读取时停止初始化，避免将读取失败误认为没有登录记录。现有会话日志不会被重写或删除。

其他账号使用 `<desktop-home>/accounts/<account-hash>`，首次工作目录位于 `Documents/NovaFlow/accounts/<account-hash>/default-workspace`。新档案仅启用 base 和 Web bundle。如果可以取得此前已登录账号的档案，会复制其已安装的第三方包文件，不执行安装脚本；不会复制启用列表、插件补丁、密钥和设置。因此这些插件显示为已安装但未启用。之后各账号分别保留启用选择，退出后重新登录也会恢复。旧账号的档案保持原样。模型容量自定义值也按账号保存，旧账号保留其已有文件。通过 CLI 管理某个隔离档案时，须完全退出桌面端，并明确将 `DSH_HOME` 设为该账号的数据主目录。

此机制隔离同一个操作系统用户下各应用账号的数据，不属于操作系统沙箱。有文件访问权限的用户或已启用插件仍可打开工作区之外的文件；明确打开同一个目录也会共享其中的文件。

## 更新与更新日志

更新来自本仓库公开的 GitHub Releases，标签格式为 `v<semver>`（仍兼容 `novaflow-v<semver>`），只提供已发布的正式版。未经用户确认不会下载或安装任何内容：每次提示都会显示更新日志，内容取自 Release 说明中 `<!-- novaflow:install-notes -->` 标记之前的部分，按纯文本显示。Windows 与 AppImage 构建在用户确认后于应用内下载，安装重启前会再次确认。没有 Developer ID 签名的 macOS 构建和 deb 安装无法原地替换，弹窗改为打开 Release 页面；这类构建在启动后检查一次，并跳过用户已选择稍后的版本，从菜单手动检查则总会给出结果。安装包不包含强制更新策略，因此不会强制更新。

## 验证与启用条件

定向无密钥测试使用模拟远端响应和真实本机回调监听器。通过 `vitest run apps/desktop/tests/novaflow-auth.spec.ts apps/desktop/tests/novaflow-routing.spec.ts apps/desktop/tests/novaflow-quota-display.spec.ts apps/desktop/tests/novaflow-model-capacity.spec.ts apps/desktop/tests/novaflow-account-ui.client.spec.ts apps/desktop/tests/novaflow-account-bridge.client.spec.ts apps/desktop/tests/host-process.spec.ts apps/desktop/tests/main-startup.spec.ts apps/desktop-host/tests/novaflow-provider.spec.ts packages/client/ui-model-selection/tests/model-select.client.spec.tsx --maxWorkers=2` 运行账号、路由、金额显示、模型容量、原生账号页面、页面桥接、模型菜单与 IPC 校验。页面集成用例连接真实账号运行时和 HTTP 授权传输，仅替换网络、存储等外部依赖；中英文可见状态快照保存在桌面测试的 `__snapshots__` 中。这些测试不验证真实账号、付费模型调用、实际操作系统钥匙串或安装后的桌面构建，jsdom 断言也不等于真实浏览器视觉验收。

品牌发行需要带有本桌面授权的 New API 服务器、设为公开来源的 ServerAddress，以及 Windows、macOS、Linux 的真实安装验收。在客户端切换分组还需要授予 `group:select` 的服务器版本；使用 auto 还需要站点把 `auto` 列入账号的可用分组，撤下后使用它的设备会退出登录，与撤下其他分组时相同。元数据未配置的容量要改用厂商目录，需要服务器提供 `capacity_defaults`。安装包只从本仓库的 GitHub Releases 读取更新，不含强制更新策略，也不使用继承自 DeepSeek Harness 的更新源。Host 适配器使用原有模型选择器，目录发布会刷新已打开的输入框。首次原生启动通过可写 profile 设置尚未选择模型的初始状态，保留用户后续保存的模型选择。目录把已保存默认模型列到另一个端点下时，默认选择随之移过去并清除推理等级。会话已选的模型不再列出时，发送前需重新选择模型。打包本身不包含这些接入。发布、真实凭证和生产调用属于独立操作。
